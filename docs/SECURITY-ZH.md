# 安全设计、限制与威胁模型（v0.1）

## 输入面

所有上游名单均视为不可信输入。HTTPS 必须校验证书、拒绝跨域跳转、限制输入体积。只允许严格格式的 IPv4/CIDR；拒绝私有、保留、文档、链路本地地址及过大的无差别网段。第三方 `.rsc` 永远不会被当作脚本执行。

`ros6_rsc` 解析器仅用于拥有合法使用授权的兼容性场景。拒绝未知指令、表达式、命令替换与非 `scaners` 地址列表，不会执行 `/import`。

## 数据发布

- 使用 GitHub Actions 公共工作流构建；`pull_request` 只运行无写权限测试，只有 `main` 定时任务能发布数据。
- 失败、异常总量、零条目、过期源、解析异常等情况拒绝构建，保留旧发布。
- 清单记录来源 URL 的官网链接、内容哈希、拒绝数量、版权署名及发布时间。
- manifest 中 SHA-256 只能证明下载后文件与 manifest 一致，**不能阻止有写权限的仓库维护者或被入侵的 Actions 工作流同时篡改两者**。建议启用 2FA、仓库审查、工作流权限最小化；后续版本可以引入离线签名公钥验证。

## RouterOS 更新

- 目标列表固定为 `scaners`，保持现有 `/ip firewall raw` 规则不动。
- 先验证预期 RAW drop 规则是否存在、正常启用，避免误操作不相关的 RouterOS。
- 通过 TLS REST 读取整个列表（最大响应 64 MiB），大列表可能需要优化分页/传输策略。
- 只按注释**严格等于** `TIPI/v1` 认领条目。旧 ros6 列表和人工条目无论过期与否都不主动删除。第一次上线上只做补充，旧 ros6 地址不会自动被新项目接管。
- 先新增，后删除本工具标记的旧条目，既不清空旧列表也不会短时出现空名单。
- 变更数量和删减比例设硬性限额。发布源异常锐减时停止，人工审批后才可调整安全阈值。
- 出错时尽最大努力重新添加已删除条目并删除本次新增条目。**RouterOS REST 不提供跨请求原子事务；断电、网络中断、多个写入器并行时，回滚可能部分失败**。不要把它宣传成全事务零风险。
- 如果 ros6 原调度器仍会全量清空 scaners 并导入，该工具无法保证持续控制所管理条目的存续。两套更新器只能在迁移阶段短期并存。

## 发布许可边界

Spamhaus DROP 官方要求使用该数据时保留 Spamhaus Project 署名和日期/版权信息；本项目在 manifest 的 source 字段保留相关元数据，公开部署前仍应根据实际发布形态核实当前 Fair Use 条款。

abuse.ch 在 2026-10-21 的条款中说明 Feodo Tracker、SSL Blacklist、YARAify 采用 CC0 原则，允许商用/非商用；但是作为威胁防护源，还需要独立检查最近更新时间。

ros6 数据源未查到明确的公开再分发授权，因此代码中默认为禁用；不会借 MIT 软件许可证推定对方数据自动变为可公开转载。

## 已知限制

- IPv4-only；IPv6 RAW 需要另外的 `/ipv6 firewall raw` 及 IPv6 情报、权限审计，不能宣称已覆盖。
- 无 per-IP 独立历史评分、威胁类型融合、DNS 黑名单、AS 信誉、ASN 自动封禁；这些属于后续阶段。
- 只用来源数据本身的 CIDR，不按“同一 /24 有 40 个扫描地址”推断整个 /24 恶意。
- 对外部 IP 列表的有效性没有100%保证，阻断可能造成合法业务故障。
- 批量 REST 添加效率受 RouterOS 性能与网络时延限制；大量变更应使用专门压测环境评估。

## 审计建议

定期记录来源时间戳、当次追加/删除数量、`scaners` 总项、RAW 计数器两次采样差值、RB5009 CPU / 空闲内存、关键游戏/代理连接可用性。后续可以将这类指标接入 RouterOS Ops UI，但不要把 RouterOS 密码或真实 IP 访问日志上传公开仓库。
